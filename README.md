# 航运智能账单助手

使用 Python + LangChain 解析航运材料，提取费用、判断 AR/AP，并匹配已有账单，输出新增、更新、重复或待复核的 JSON 记录。

## 使用

1. 首次使用运行 `setup.cmd` 安装依赖（Python 3.11+），之后运行 `start.cmd`。
2. 浏览器打开 <http://127.0.0.1:8765>，点击“运行题目样例”，或上传自己的文件并填写记账主体。
3. 在线使用大模型和题目指定 OCR 时，按 [使用说明](使用说明.md) 配置 `.env` 和文件下载地址。

[补充思考](补充思考.md) 包含项目说明、Harness 设计和五条业务与实现思考。

## 对照题目

| 要求 | 实现 |
|---|---|
| Python、LangChain | LangChain 编排解析、提取、校验、匹配流程；大模型返回 Pydantic 结构化结果 |
| EML 正文、邮件头和附件 | 优先读取纯文本，HTML 作备选；附件递归解析，记录来源 |
| PDF、图片和指定 OCR | 在线模式按题目协议调用 `/process`；本地模式使用 PDF 文本层和 RapidOCR |
| XLS/XLSX、DOC/DOCX | 读取工作表、正文和费用表格；旧 DOC 通过本机 Word 只读读取 |
| 单据和费用提取 | 类型、编号、日期、交易方、提单号、扩展号、箱号、费用、金额、数量、单价、币种、付款方式和合计 |
| 标准化 | 保留原费用名，映射标准费用名、三位币种与 PP/CC |
| 新增和增量更新 | 按题目四类条件匹配；只更新明确指定字段，未提供字段继承旧账 |
| AR/AP | 根据当前记账主体与交易收付方判断，贷项或负数另标余额减少 |
| 校验和重复冲突 | 核对原文、金额、币种、数量单价、合计与置信度；重复不新增，冲突待复核 |
| 标准 JSON 与处理依据 | 每费用一条；未知为 null，金额为数字；保留原文、来源和字段修改前后值 |

## 稳定性设计（harness）

模型只提取候选数据；程序检查结构、原文证据、金额合计及匹配条件后决定操作。解析失败、OCR 错误、低置信度或多条匹配统一进入待复核。调用设置超时，文件及附件数量设置上限。测试使用真实样例和可人工核对的业务用例，防止修改后破坏既有行为。

## 文件

- `shipping_agent/`：解析、OCR、提取、标准化、账单匹配及网页接口。
- `web/`：中文操作界面。
- `samples/original/`：原 ZIP 解压的四份材料。
- `examples/`：新增、更新、已有账单和 OCR 配置示例。
- `scripts/`：安装、启动、旧 DOC 读取及代码打包。
- `output/`：运行生成的费用 JSON、审计结果和账单快照建议。

## 打包

```powershell
.\.venv\Scripts\python.exe scripts\build_submission.py
```

提交包生成在 `dist/shipping-bill-agent-submission.zip`。

本地模式已用真实材料验证；LangChain 与指定 OCR 的请求及返回流程使用本地模拟服务测试。真实外部联调需要填写模型密钥及 OCR 可访问的原件 URL。
